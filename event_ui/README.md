# 人工事件录入工具

独立新窗口程序，不改动原单局面 `test_ui`。仅复用其牌面绘制组件。

2026-11-12：分析方法新增 `fixed-v2`，可在“v2 权重 JSON”输入如 `{"risk":12}` 后应用；摘要支持滚动，避免较长的攻防说明被截断。参数见 [v2 说明](../docs/fixed-v2.md)。此工具仍仅适配人工记录，不是天凤牌谱回放 UI。

```powershell

```

IDE 也可运行根目录 `run_event_ui.py`，解释器选择项目 `.venv`。原工具继续用 `python -m test_ui`。

## 建立记录

默认是自己（0 家）庄家首次待弃牌的简化开局。上方输入 13 张手牌、第 14 张和宝牌指示牌，牌码用空格分隔，未知牌用 `?`。选择“中途”可指定待摸牌/待弃牌和当前行动家，并填四家已经知道的牌河。

中途入口假定无副露，其他家暗手只记 13/14 张数量。没有填入的历史不能当成不存在；仅在确认公开牌全部输入时勾选“中途公开牌已全部录入”。未提供的点数、资格和余牌数量保持未知。按“按输入新建”会替换内存中的当前记录，需要保留时请先保存。

## 录入一轮

1. 自己弃牌：点击图形手牌选中，再按“记录弃牌”。手切/摸切可以明确选择，也可以保持未知。若所选手牌本来未知，可在牌面下拉框选择其此次公开牌面。
2. 当前进入响应窗口；只有确实无鸣牌、无和牌时，才能按“确认无鸣牌 / 无和牌，继续”。
3. 下一家待摸牌：按“记录摸牌”。对手暗摸自动记录未知，牌面输入禁用。
4. 对手弃牌：选择实际公开的牌面，再按“记录弃牌”，然后确认本次响应结果。
5. 轮到自己摸牌时，选择实际摸入牌面，再记录摸牌；手牌和基础分析随事件刷新。

发生吃、碰、杠、立直、和牌、流局等未支持动作时，选择对应原因并按“记录未支持动作并暂停”，不要按无人响应跳过。暂停不会伪造副露或结算；其后无法继续摸打。

手牌、摸牌、指示牌、四家牌河、行动阶段、事件历史与基础分析在同一窗口不同区域展示。点击手牌只分析，只有记录按钮会改变牌局。

## 保存、回放与纠错

- 输入记录文件路径后保存；已有文件需勾选“允许覆盖”。保存的是完整事件记录，即使正在查看过去的某一步也不截断记录。
- 加载只支持新的 `nanikiru-manual-v1` 文件；旧 examples JSON 不是此格式。加载失败保留当前记录。
- 点击事件历史某行进行只读回放，0 是接入快照。回放期间推进与撤销按钮禁用；“回到最新”恢复录入。
- “撤销最后一步”撤销末尾事件并重新计算，不改写旧文件；可继续撤销以更正较早的误录，之后重新输入。
- 每次推进、撤销或加载都更新版本和分析。牌效仅说明形状与未见进张，不代表完整行动许可。

## 分析调度与输入输出

当前方法默认 minimal-shape-v1，支持向听、等待、弃牌比较与条件牌效排序。basic-v1 不支持排序，切换时需取消“牌效排序”，否则明确报错。

默认自动分析；关闭“自动”后按“分析当前时点”。点击手牌只展示已返回的对应候选；回放会提取所选时点的历史前缀，推进或切换设置会清除旧结果。勾选 JSON 后在同一窗口下方并排查看实际 AnalysisRequest 与 AnalysisResult，未知显示为 {"$unknown": true}。

公开信息不全时进张未知，排序仅比较向听；没有完整动作许可，因此输出为条件牌效偏好，不是可执行建议。接口与限制见[分析调用链](../docs/analysis-pipeline.md)。
