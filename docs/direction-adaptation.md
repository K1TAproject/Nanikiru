# 新方向适配记录

日期：2026-11-10。用户已授权修改底层结构、适配必要计算、删除不适配或冗余内容、停用旧 UI；本轮不实施后续完整函数功能。

## 已完成

- 五种基础记录已替换旧数据对象，牌码包含赤牌，资格不作为玩家独立字段保存。
- 处理/分析请求与结果契约、三态合法性及确定/条件/预测结果区分已落地。
- 明确 UNKNOWN、None 和集合 completeness；构造器检查结构、库存与部分关系，不代替完整规则引擎。
- 保留并适配牌形、库存、等待、条件算分、振听条件组合和食替纯计算。
- 移除旧 Tk UI、启动入口、完整 Game/Recorder、机器人、耦合的启发式策略/推进/复盘和存档兼容运行链。
- 删除上述功能专用测试、旧 UI 检查图片与日志、失效功能文档；新测试继承并改写仍相关的算分/牌形固定案例。
- 旧 examples/*.json 原样保留为历史数据，没有静默迁移或删除。

## 保留与删除依据

| 旧组件 | 处理 | 原因 |
| --- | --- | --- |
| models.py | 替换为五结构 | 旧手牌/副露/资格对象不再是权威表示 |
| efficiency.py | 保留独立牌形/库存，改用新快照和牌码 | 可复用计算；删除评分汇总、绑定旧动作的排名与复盘 |
| scoring.py | 保留算分适配、等待、振听条件组合 | 不必重写番符算法；不保留旧 PlayerState/Rules 兼容壳 |
| call_rules.py | 改传牌码与鸣牌类型 | 小型独立规则工具可复用 |
| Game / Recorder | 删除活动实现 | 全知推进、响应裁决、存档和分析耦合；本轮不重建新处理引擎 |
| bot / decision / defense / tenpai / progression / riichi_decision | 删除旧集成实现 | 依赖旧观察字典、隐式资格和合法动作；未来按新接口实现，不保留双套状态 |
| UI / comparison / run_game / run_debug | 删除 | 用户停用旧界面，避免假入口和不必要 Tk 依赖链 |
| 旧 JSON 样例 | 保留并说明 | 是历史数据，不应为代码清理而损坏 |

这是有意的 API 破坏性调整。`Tile`、`Game`、`Recorder` 等旧导入不再可用；v7/Recorder v1 数据没有新加载器。没有“旧代码仍兼容”的承诺。旧规则文档保留作计算基准/历史参考，旧通过数量不是当前通过数量。
