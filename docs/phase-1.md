## 1. 数据模型与记录约定

实现牌、玩家、手牌、单局阶段和基础动作类型。区分固定座位与自风、未知牌与无牌、摸入牌与原有暗手牌。

验收：能构造带既有副露或立直的中途快照，自家手牌明确、对手暗手数量明确；拒绝非法牌值和矛盾快照；不要求接入前事件历史。

## 2. 普通摸打与统一提交入口

实现自家已知摸牌、对手未知摸牌、弃牌及无人响应后继续摸牌的流程。校验先于状态和历史更新，非法输入不能产生部分修改。

验收：连续数巡手牌数量、牌河、阶段和剩余可摸数正确；拒绝自家打不存在的牌、错误行动者或连续摸牌等非法序列。剩余数为零后拒绝新摸牌，但不跳过最后弃牌；测试停止不产生虚构流局或点数变化。

## 3. 保存、加载、回放与最近动作撤销

使用 JSON 保存格式版本、初始局面和顺序事件。支持回放到指定位置；撤销最近动作可通过重新回放实现。任意历史修正及依赖事件处理不默认纳入首个闭环。

验收：保存加载结果一致；重复回放确定一致；撤销恢复正确状态；初始局面未被运行状态污染。

## 4. 后续扩展：吃、碰、杠（不在首次交付中）

增加吃碰、明杠、暗杠、加杠、补牌及宝牌指示牌更新，关联来源弃牌。处理加杠响应阶段，明确事件顺序。

验收：各类动作有成功与失败案例；鸣牌者和张数正确；来源牌不重复计数；非法动作不污染历史。

## 5. 后续扩展：立直与麻将结果（不在首次交付中）

以后记录立直宣言、宣言牌与成立；在明确规则边界内处理立直后约束。自摸、荣和、流局与结算是后续候选范围，需在对应任务明确，当前不实现。

验收：单局可结束，结束后拒绝摸打；点数和供托符合已确定的结算约定。明确列出尚未实现的听牌、役种或其他合法性校验。

## 6. 一致性与错误反馈

检查已知牌数量、手牌副露数量、阶段、动作来源和已使用弃牌。根据可见信息区分可确定错误与无法验证的条件。

验收：故意错误的案例得到具体原因；未知暗手不被冒充为已验证；所有拒绝操作保持状态和历史不变。

## 7. 完整序列与最终交付

首次交付准备从合法中途快照到可摸牌耗尽的完整支持序列，执行普通摸打、结束、保存、加载与回放；另测提前停止、保存后继续、撤销、初始副露去重及初始立直状态。不是完整和牌或流局裁判测试。新增鸣牌与立直分支在实现后再补充。

交付：

- 可导入的 Python 记录库。
- 可直接运行的手动提交示例。
- 示例对局 JSON。
- 覆盖核心约束的自动化验证。
- 使用说明及支持范围、已知限制。

最终通过标准：相同初始局面和事件始终还原相同状态；非法输入不破坏已有记录；完整示例可独立运行并通过验证。

## 实施节奏

首次交付完成第 1～3 步及对应的第 6～7 步校验、示例，包含牌山耗尽与手动停止。第 4～5 步留到后续。每步完成后记录实际验证结果，未通过或未实现的内容保持待办，不因文档中已有设计而标记完成。
