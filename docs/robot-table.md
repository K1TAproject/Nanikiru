# 机器人牌桌

独立入口 `python -m table_ui`（或 `run_table_ui.py`）。复用现有单局模拟器，使用 A 规 `tenhou_hanchan()`；原单局面 `test_ui/` 不变。

## 操作

1. 在项目目录运行 `.\.venv\Scripts\python.exe -m table_ui`。
2. 四家分别选择“人工”“v1 牌效”“默认 v2”或“拟合 v2”。初始为 0 家人工，其余 v1。
3. 观察拟合策略时，将 0 家设为“拟合 v2”，点击“开始自动”；也可“机器人单步”。遇到人工座位会等待操作。
4. 手动操作时切换到该家主视角，点击手牌选弃牌，或从动作列表选择吃、碰、杠、立直、和牌等，点击“执行所选动作”。
5. 右侧独立选择主视角分析方法，查看推荐、候选、事件、结算和真实分析输入／输出 JSON。点击手牌可查看该牌的切后指标。主视角分析方法不改变各家的机器人配置。
6. 可暂停、撤销一步、保存及载入。种子用于复现发牌；相同方法和权重使用固定并列选择。

默认加载 `data/external-replays/v2-round1-A-retry-01/fit/weights.json`，也可选择其他权重。加载要求同目录 `report.json` 与权重一致，且报告为已完成的 A 规数据。缺失或不匹配会提示，不会悄悄以默认参数冒充拟合结果。

四方牌桌显示手牌、摸牌、牌河、副露、宝牌指示牌、分数与局况；对手暗手显示牌背，和牌结束后展示公开的和牌手牌。所有区域在同一窗口。

## 机器人接口

`nanikiru.arena.Session` 负责可见请求和动作执行边界，`table_ui/` 只做显示及调度。自定义机器人只接收 `AnalysisRequest`，返回 `Action`：

```python
from nanikiru.arena import Session, inspect_turn

session = Session()
def bot(request):
    return inspect_turn(request).action

while session.game.phase != 'ended':
    session.step(mode='默认 v2', bot=bot)
```

使用拟合策略可调用 `session.step(mode='拟合 v2', weights=load_weights(path))`。逐座位控制使用 `acting_seat()`、`turn(seat, mode, weights)`、`inspect_turn(turn.request)` 和 `submit(turn, decision.action)`。

请求只来自行动者可见记录，不含真实牌山、种子或对手暗手。模拟器实体牌 ID 在请求边界转为不携带牌山位置的临时别名；机器人必须返回当前请求中的 ID。提交时校验版本、行动者、响应目标及引擎合法动作，并转换观察者局部事件 ID。过期或非法建议会拒绝执行，UI 暂停并提示，不暗中替换为另一动作。

分析在后台线程运行，窗口保持可操作；刷新后旧结果不能用于新局面。存档是包含私有信息的模拟器完整存档，与策略输入不同。

## 能力边界与验证

- 当前完整推进一局，到和牌或流局结算停止；尚不自动连续开局完成整场半庄。
- v1 采用最小向听／最大进张，辅以合法和牌优先及不鸣牌时跳过；默认 v2 与拟合 v2 使用综合动作推荐。
- 本轮拟合仅训练弃牌／立直候选。鸣牌仍用 v2 启发式；评分和危险指数不是校准概率，能跑完对局不代表策略强度得到证明。
