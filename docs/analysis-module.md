## 职责与调用路径

分析模块接收处理模块保证一致的可见事实与明确未知，计算派生结论，不纠正识别、不维护第二份牌局、不修改输入。未知不会自动变成零、false 或空集合。

```text
RoundSnapshot → analysis/basic.py 的指标包装 → analysis/efficiency.py / rules/scoring.py
显式假设条件 → score_hand            → rules.scoring.evaluate

RoundRecord 前缀 → AnalysisRequest → analyze 调度 → 基础指标/最小排序 → AnalysisResult
```

以上调用路径均已实现，调度范围与输出界面见[分析调用链](analysis-pipeline.md)。`analysis/basic.py` 不建立新类；复用 Metric、Action、CandidateResult。牌效计算和 mahjong 2.0.0 番符计算继续复用，避免并行维护另一套算法。

## 已实现功能

1. **向听数**：完整自家牌形的最小向听，支持 13/14 张等价牌形、普通形及无组时的七对子/国士；成形 -1，听牌形 0。不需要知道对手手牌或牌山。
2. **理论等待**：列出可使牌形成和的牌类，公开信息完整时附未见枚数。公开信息不全仍能列等待；已见耗尽的等待仍保留并标 0。理论等待不保证有役或允许荣和。
3. **指定弃牌牌效**：按实体 ID 比较弃牌后的向听、改善牌和未见进张数。弃牌仍是已见牌，不会错误地加回库存。只作候选评价，不授予行动许可、不自动选择最优牌。
4. **条件打点**：在指定和牌方式、风、立直、宝牌及特殊条件下返回有役与否、番符、支付。区分未知条件、未成形、无役和已检测到的条件冲突。即使精确算出支付，也只返回 conditional，因为未验证实际和牌许可。
5. **最小牌效排序**：复用各候选的 Metric，先最小向听、再最大未见进张数，同分并列。未知进张时只比较向听；未知向听时不作完整排序。输出是条件牌效偏好，不改变动作合法性、不生成可执行推荐。

独立 `test_ui` 目录提供单窗口验证：随机发牌或从全部牌种手动组牌，显示已排序 13 张手牌、独立摸牌、宝牌指示牌、点击分析与并列推荐；图形牌面不依赖外部素材。它不属于分析核心，没有恢复旧 UI 或完整对局推进。

条件打点可以供后续比较立直与默听、不同和牌张的价值。里宝未知时不能直接输出“实际立直打点”；可显式传 `ura=()` 计算无里宝假设，并在 details 中保留假设，不把它当作里宝期望值。

## 未知的处理示例

| 输入情况 | 可以返回 | 不能返回 |
| --- | --- | --- |
| 自家手牌完整、公开牌覆盖未知 | 向听、理论等待和改善牌 | 精确未见枚数/ukeire |
| 自家有未知牌或可能漏了整组 | 不依赖该牌形的其他未来分析 | 唯一确定向听/等待；当前相应指标 unavailable |
| 只有完整当前快照，没有之前行为 | 当前牌形；显式假设下的打点 | 从历史推断振听、一发或立直后行动许可 |
| 特殊计分条件显式传 UNKNOWN | 缺失字段原因 | 该条件下完整精确打点 |
| 对手暗手未知 | 不影响自身确定性牌形计算 | 对手真实等待、保证安全或真实和牌概率 |

支持 unknown 的含义是正确区分可计算与不可计算的结论，并非任意缺失下都能输出相同数值。当前未实现未知牌枚举、上下界、条件分支树或概率补全。

## 运行示例

从项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m examples.analyze_basics
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

示例使用自己的构造快照，不加载旧 JSON、不启动 UI。展示四种内部调用：向听 0；等待 3s/6s，分别未见 3/4 枚；指定弃牌后 ukeire=7，合法性仍 unknown；在示例显式条件下自摸 3 番 30 符，庄家每家支付 2000。最后一项不包含本场供托，也不是允许和牌的判定。

已实现[完整/不完整观察器](observation.md)，生成可复现的中途接入、牌码及手摸切缺失样本；v1/v2 按字段依赖降级。批量导出与实验见该文档。

已新增 [人工参数 v2](fixed-v2.md)：可调权重，比较牌效、条件打点和启发式风险，输出综合/进攻/防守弃牌偏好。分析调度尚未实现全动作查询、实际和牌许可任务、吃碰杠分支评价、风险概率或模型训练。新模拟器已实现规则推进与结算，见[模拟器说明](simulator.md)；分析从完整模拟观察共享弃牌许可查询。已有最小牌效排序，不输出虚构概率；完整模拟观察可输出合法弃牌推荐，人工历史不足时仅输出条件偏好；analyze() 已实际调用基础计算与最小排序。

独立处理模块已经实现摸打、响应结束、暂停和记录回放，见[人工推进说明](manual-progression.md)；分析核心不依赖它，事件 UI 通过玩家视角提取、标准请求与调度器取得统一结果。当前全部测试为 121 项（此前 109 项，观察器阶段新增 12 项），原单局面工具未改动。

已有 [天凤本地适配器](tenhou-adapter.md) 可产弃牌样本。下一步可建立固定验证集评估人工权重，再扩展鸣牌/立直策略和训练模型。训练数据只使用决策时可见信息，未来结果单独作为标签，不能混入当前快照。
