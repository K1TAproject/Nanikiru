## 本轮实现与基准

- `Game()` 默认随机种子，`Game(seed=...)` 可复现，存档保留实际种子和初始牌山。
- 支持全人工调试，默认庄家人工、其余三家由基础牌效机器人提交；弃牌和暗杠/加杠宣言后，三家按座位顺序响应，全部收集后统一处理。荣和优先于碰/杠，碰/杠优先于吃；双响成立，三家荣和流局。本场及供托给距放铳者最近的和家。
- 吃仅上家；禁止现物和筋食替。吃碰后不摸牌，直接弃牌。海底牌不允许吃碰杠；杠需剩余活牌及岭上容量，第五杠禁止。
- 立直需门清、至少 1000 点、弃后听牌和至少 4 张活牌。三家响应结束且宣言牌未放铳才扣棒；可振听立直。支持双立直、一发；成立后只能摸切或合法暗杠、自摸/荣和。
- 立直后暗杠必须使用新摸的第四张并保持全部听牌不变，禁止送杠；不额外禁止拆分方式/役种改变。暗杠即时翻新宝，明杠/加杠于弃牌或下一次岭上摸牌前补翻。抢杠成立不补牌、不翻该杠新宝；国士可抢暗杠。
- 支持舍牌振听、临时振听（下次自己的摸牌解除）、立直后见逃永久振听。无役完成形的见逃也按规则处理；普通形不能因无法抢暗杠而产生临时振听。
- 和牌支持常见普通役、役满、七对子/国士、宝牌/里宝/赤宝、场风/自风、海底/河底/岭上/抢杠、天和/地和。食断、后付开启；不切上满贯；累计役满上限一倍，双倍役满开启，不加地方役。
- 大三元/大四喜包牌按公开副露来源判定；自摸由责任家支付，第三家放铳时折半，包牌承担本场。按当前基准复合役满一并承担；无四杠子包牌。
- 流局包括九种九牌（人工声明）、四风连打、四家立直、三家荣和、四杠散了、荒牌与流局满贯。多人合计第四杠后允许岭上和及弃牌荣和，之后流局；一人四杠继续。
- 荒牌按形式听牌结算总计 3000 点；供托留存，听牌庄连庄。流局满贯作为荒牌支付替代：牌河全幺九且未被鸣走，自家副露不取消资格；多家逐一支付满贯，不另加不听罚符，不收取本场/供托，按庄家听牌决定连庄。途中流局无不听罚符并连庄。
- 结果包含结算前后点数、支付、本场/供托、下一庄家/场风/局数；不自动进入下一局。
- 非法动作在副本上失败，原局面、牌山、点数、已收合法响应和合法历史不变；暂停并保存诊断。恢复须显式调用 `resume()`，撤销不自动恢复。
- 当前 v4 存档增加独立役种决策记录，兼容 v2/v3；役种基准见 `yaku-decisions.md`，详见 `efficiency-review.md`。支持待响应与结束局面；明确拒绝旧 Game v1，旧 Recorder v1 不变。回放位置按提交动作计数，包含“过”，自动事件跟随触发动作。

用户已确认的是阶段功能与前述介入语义；具体边界采用本轮向用户说明的开发默认，不宣称与雀魂逐条一致。本地基准参考 [天凤四人规则官方手册](https://cdn.tenhou.net/man/#RULE)，并显式固定上述分歧项；后续如需完整雀魂一致性，需要另作规则对照。

## 建议实施顺序与验收

### 1. 规则基准与合法动作

- 确认采用的四人东规则版本及配置，写成具体规则清单，并在实现前核对来源。
- 确定和牌形、役、番符、振听、立直资格等依赖的实现边界。
- 向指定玩家提供其合法操作；其他玩家的可响应项目不能泄漏到玩家观察或日志中。
- 不提前建设多规则插件框架，先支持一套明确规则。

验收：合法/非法动作牌例有明确预期；无役和牌与振听等不能仅凭完成牌型放行。

### 2. 响应收集与裁决

- 弃牌后进入响应窗口，处理荣和、吃碰杠与过；必要响应完成后才推进摸牌。
- 明确同时响应、动作优先级、多家荣和及无人响应的处理。
- 响应以玩家决策记录，涉及振听的放弃和牌不得被无依据的自动过牌替代。
- 内部待响应集合及未决响应保持私有；玩家只收到自己有权看到的信息。

验收：先提交低优先级动作不会抢先截断其他合法响应；不会重复摸牌；响应中保存、加载、回放一致；非法动作不改变牌、点数、有效响应和合法事件历史，但按新要求进入暂停介入状态。

### 3. 吃碰杠与牌山变化

- 吃碰及明杠引用来源弃牌，正确扣手牌、增加副露并改变行动者。
- 加杠、暗杠、抢杠响应、岭上补牌和新杠宝按确认规则处理。
- 核对保留牌区和可摸牌区变化，继续保证全部牌库存守恒。
- UI 显示可选组合，区分赤牌与普通五；副露方向和来源可辨认。

验收：各类杠、补牌、指示牌及中断分支独立覆盖，不重复计数，不在响应完成前错误翻宝或补牌。

### 4. 立直与和牌

- 立直宣言、宣言弃牌、成立及供托扣除分阶段处理，按规则校验资格。
- 处理立直后的限制、振听、一发相关状态，以及自摸和荣和。
- 和牌结果展示牌型、役、宝牌、番符及支付明细；不以手动填写分数代替用户未确认的自动结算。

验收：宣言牌被荣和等边界正确；普通形、七对子、国士等牌例及无役、振听反例有可核对答案。

### 5. 流局与结算

- 荒牌流局的听牌判定、不听罚符，以及确认纳入的途中流局类型。
- 按规则处理供托、本场、点数变化、连庄信息；本阶段只结算单局，不自动推进下一局或整场排名，结果需保留后续连续多局所需信息。
- 结束后拒绝无关动作；暂停仍只是暂停，不能当作流局。

验收：结算前后点数与供托一致，包含多人和牌/途中流局等已纳入规则的分支；结束结果可保存回放。

### 6. 图形界面、回放与兼容

- 当前玩家选择自己的合法动作；全知模式可辅助逐家测试，但不得改变核心裁决规则。
- 牌桌显示副露、立直宣言牌和结果面板；保留错误、测试输出和视角过滤。
- 不同玩家视角的事件和 JSON 继续过滤隐藏信息；结局公开什么信息也由规则确定。
- 动作类型增多后重新定义回放位置含义，避免仍将“所有动作数”标为“弃牌数”。
- 采用明确的新存档版本；原游戏 v1 的自动摸牌行为需兼容或清晰拒绝/迁移，不能按新响应规则静默重放出不同结果。旧 Recorder 及其测试保留。

验收：真实窗口操作覆盖响应、鸣牌和结果展示；所有新测试与适用旧测试通过。

## 本轮用户已确认

1. 默认普通四人东风局，但场风应为变量，算法支持南、西等场风，不能在役种、符数或观察输出中写死东风。场风与玩家自风分开；暂不建设整场调度。
2. 纳入正常立直判定、杠开新宝流程，以及四风连打、四家立直、四杠散了等普通流程。荒牌流局与其他标准结束分支一并列入规则清单核对，不能把“四杠”简单理解为任何人开到第四杠立即结束。
3. 集中实现单局自动结算，数据设计考虑后续多局：保留结算前后点数、供托归属、本场变化、庄家是否继续等必要结果，不提前实现完整连续对局管理器。
4. 先评估日麻算分库；无需直接整体 import，可以参考算法用本地代码实现。该答复不是禁止依赖，也不是批准未经评估复制源码；实现方式需依据评估说明。
5. 后续支持是否包含赤宝、是否开新杠宝等选择。建议本阶段引入最小规则字段 `aka_dora_enabled`、`kan_dora_enabled`，默认开启，开局固定并随存档保存，不在对局中途改变规则。用户已明确：关闭赤宝只取消赤宝加番，保留赤五牌面和身份，不替换成普通五。
6. 每次弃牌后，其他三家依次确认自己的响应或“过”，全部收集后统一裁决；不能因只有低优先级响应已到达就提前执行。玩家自己的可选动作可以显示，其他人的未决响应不公开。
7. 对非法操作必须执行合法性检查并暂停介入，例：吃对家/下家、立直后的非法鸣牌或改变听牌的杠、食替。已存在暂停入口不等于此需求已实现。

## 非法操作与规则开关的已确认语义

- 合法菜单不能代替核心校验：脚本、UI 和未来机器人均走同一检查。
- 吃仅能取上家的弃牌；副露组合、牌来源和赤牌选择均须核对。
- 立直后的吃碰明杠等限制、立直后暗杠的例外条件分别检查，不能把“不改变听牌”当成所有规则下唯一充分条件。
- 食替限制需要保留到鸣牌后的弃牌阶段，不能只在提交鸣牌时检查一次。
- 非法请求不消耗手牌/牌山、不改变点数、不写成成功动作，不清除已合法提交的响应；暂停标记与介入诊断单独保存，保证可追溯。
- 对玩家可见的错误说明也须过滤暗手信息；全知诊断只能通过调试入口访问。
- 用户已确认：保留最后合法局面和已提交的合法响应，显示错误原因；测试人员修正操作，或撤销到此前步骤，再明确恢复。不提供强行放行非法动作，也不自动扣分判罚。未执行撤销时保留已有合法响应；主动回退时按回退位置恢复历史。修正输入或撤销本身不自动解除暂停。
- 用户已确认：关闭赤宝时保留赤五牌面、牌张身份及原有库存，只取消赤宝加番。普通宝牌、杠宝和里宝按各自适用规则独立计算，赤五仍可作为对应五计入这些宝牌，不能把赤五完全排除在宝牌计算之外。
- 实现建议（尚未单独确认）：关闭新杠宝只停止新增指示牌，保留正常杠、补牌和四杠相关规则。
- 新增验收：非法响应后牌山、点数、有效响应和合法历史保持不变，仅增加暂停/诊断；修正或撤销后仍须明确恢复。相同初始牌山与动作在赤宝开关两种设置下保留相同牌面和身份，只改变适用的赤宝加番及由此产生的结算结果。
