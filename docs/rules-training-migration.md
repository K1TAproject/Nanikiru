# 当前训练规则与跨规则迁移

核对日期：2026-11-14。本文说明现有能力与未来迁移步骤，不代表已经实施 B 规训练。

## A 规是什么

当前正式目标是天凤段位战四人半庄、食断有赤，配置为 `tenhou_hanchan()`，标识 `tenhou-4p-hanchan-2026-v1`。本地使用 2026 凤凰桌年度包；第一轮固定选择 1,000 场，分为 802 场训练、118 场验证、80 场测试。Hugging Face 同一仓库还包含其他年份及雀魂来源，不能因都采用 MJAI 就按同一规则混用。

规则来源：[天凤官方规则及役种说明](https://cdn.tenhou.net/man/#RULE)。项目核查记录见 [天凤规则](tenhou-rules.md)，实际配置见 `nanikiru/rules/config.py`。

### 关键条件

- 双荣和成立；三家同时荣和时流局。双荣和各付本体点数，本场与供托由从放铳者起按行牌顺序最近的和家取得，庄家在赢家中则连庄。三家荣和流局不按三份和牌结算，供托留存并连庄。
- 特殊双倍役满关闭：国士十三面、四暗刻单骑、纯正九莲、大四喜各自仍是一个役满。不同役满可以复合，例如大三元加字一色为两个役满。累计役满开启；普通番数达到 13 番按一个累计役满计算，不因达到 26 番变为双倍累计役满。
- 不允许国士无双抢暗杠，但可以抢满足和牌条件的加杠。例如国士缺一万、已有其他幺九对子，对方将一万碰升级为加杠时，可以抢该第四枚一万。仍需满足非振听等条件；不能把禁止抢暗杠误解成禁止国士抢一切杠。
- 加杠第一次宣言被抢时可保留一发条件；完成加杠后中断一发，连续加杠不能重复保留。暗杠宝牌即时翻开，明杠/加杠宝牌延迟翻开。

## 现有接口能否表示 B 规

主链路已经是 `来源牌谱 -> 四家可见记录 -> AnalysisRequest.position.rules -> 合法动作/打点/特征 -> 排序结果`。`RoundSnapshot.rules` 保存完整不可变 `RuleConfig`，不只保存规则名字；隐藏手牌、未来信息与结果标签仍分离。

`rule_id=riichi-4p-v1` 是现有四人数据契约标识，不能代替天凤预设版本或完整规则配置。MJAI 主要表达动作，并不完整声明规则；导入时必须通过可靠来源另行核对规则。

| 变更 | 已有支持 | 仍需做的事 |
| --- | --- | --- |
| 允许国士抢暗杠 | `kokushi_ankan_ron` 已影响模拟器和分析器；事件中已有暗杠宣言、响应阶段和荣和对象 | 建立 B 来源核对与规则预设；验证输入覆盖；补足相关训练/评测局面。缺少私有过和信息时仍只能给条件许可 |
| 特殊双倍役满 | `double_yakuman` 已接入算分 | 按 B 规则重算特征、验证支付及包牌组合，重新评价/拟合权重；不能改写 A 原谱终局点数冒充 B 实战 |
| 双荣和、三家荣和变化 | 已有 `multiple_ron`、`triple_ron_draw` 等配置及结算路径 | 核对 B 的完整组合；只改一个开关可能不足以描述头跳、三家处理与本场分配的整体约定 |
| 有赤变无赤 | 牌码能区分赤五与普通五，计分开关已经存在 | **尚未完整支持无赤库存**，需要下述适配；不是仅设 `aka_dora=False` |
| B 的正式训练 | 单一自定义规则可走 experimental 实验入口 | 当前正式来源核对只接受天凤 A 预设；需增加经核对的 B 配置，保持独立缓存与实验报告 |

### 无赤的具体缺口

`tiles.physical_capacity()` 固定普通五 3 枚、赤五 1 枚；`counts34()`、快照校验、模拟器牌山、v2 未见牌枚举及算分实体分配沿用此库存。XML 固定实体编号 16/52/88 为赤五；MJAI 分配器同样沿用该库存，并明确拒绝 `aka_flag=False`。

所以当前 `aka_dora=False` 的含义是赤色牌不计额外番数，不是牌山已经变成各四枚普通五。正式无赤支持必须统一调整库存定义、两种适配器映射、快照验证、模拟器、分析枚数和算分分配，保留每种基础牌最多四枚的约束。无需因此推翻 TileRecord 等五种结构，但相关校验函数必须获得一致的库存上下文。不能仅把 0p 字符串替换成 5p 后绕开检查。

目前单个 `double_yakuman` 布尔值也只能表示现有整组约定，不能描述“只把国士十三面算双倍、其余保持单倍”等所有地方变体；遇到这种 B 规则才扩展字段。

## 如何训练 B 规

1. 固定 B 的完整规则及版本，先测试合法动作、打点、结算和观察投影，尤其新旧规则会产生不同结果的边界。
2. 优先收集真实 B 来源，保留其实际规则、历史动作和结算。原始 A 数据继续标为 A，不因研究目标改变而改名。
3. 从 B 原始事件重建标准输入，按 B 生成合法候选、打点与路线等特征；重新生成缓存，不复用 A 的特征或终局收益标签。
4. 当前固定 v2 可先把 A 权重作为 B 的迁移基线，再在 B 训练集上拟合，验证集选参，最后一次性检查 B 测试集。也与人工默认参数直接在 B 上的结果比较，确认迁移是否有帮助。
5. 按整场来源分区；若保留原始/转换/缺失观察等多个版本，同一原始对局的所有版本必须同区。评测同时关注规则合法性、模仿排序以及 B 特有边界；策略强度还需要之后在 B 环境中的对战评测。

现有 `fit --initial` 能读取初始参数，但 `weights.json` 目前仅含权重，完整训练规则存于报告/缓存。未来正式并行使用 A/B 时应增加模型产物的适用规则与版本校验；当前不能声称加载权重会自动拒绝跨规则使用。

### A 数据可以复用到什么程度

向听、基础组合等共通知识与参数初始化可以复用。A 局面也能用于明确标记的 B 反事实计算实验，但 A 人类动作是按 A 做出的选择，不能直接当作 B 最优动作标签。

去掉赤牌会改变价值与决策；重新算分也不能恢复“这些玩家若在 B 中会怎样打”的整条轨迹。允许国士抢暗杠可能让 B 在某个时点提前结束，A 后续事件与终局收益就不能继续作为该 B 轨迹的真实结果。

针对新允许的抢暗杠，“合法和牌应当可执行”应由规则函数直接保证，不必等待训练学会。当前只抽弃牌/立直标签，即使拥有 B 牌谱，也不会自动学会鸣牌、杠、和牌/过等全动作选择；需要另行扩展决策点和明确响应标签。不能把来源未记录的 pass 自动解释为主动拒绝合法和牌。

若未来采用神经网络，可用 A 预训练后在 B 上微调；也可用显式规则编码和合法动作屏蔽训练多规则模型。但模型必须实际消费规则特征，且各目标规则有训练覆盖；JSON 中携带规则字段本身不等于模型已学会按规则变化。当前尚未实现这套神经网络训练链。
