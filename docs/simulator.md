# 连续单局模拟器

更新：2026-11-11。已按本轮确认实现四人日麻连续单局：配牌、摸打、响应、鸣牌、立直、和牌、流局及支付。只结束当前单局并输出下一局场况，不自动开始下一局，也不做整场排名结算。

## 默认规则与明确边界

`nanikiru.rules.config.RuleConfig` 是不可变配置，随全知存档、玩家观察快照和分析请求保存。每局固定，UI 调整只用于新局。设置包括食断、杠宝、里宝、杠里宝、赤宝、禁止食替、多家荣和、一发、击飞、切上满贯、累计役满、特殊双倍役满、流局满贯、途中流局与包牌；另有起点与东/南场制。

| 项目 | 当前默认及固定处理 |
| --- | --- |
| 起点与场制 | 25000 点、东风场；可设置四家实际点数、场风、局数、庄家、本场、供托 |
| 赤牌 | 每门一赤三普通五；关闭赤宝只取消加番，不改变库存 |
| 食断、后付 | 开启；食断可关闭，不实现地方役 |
| 食替 | 禁止现物和筋食替；可关闭 |
| 响应 | 荣和高于碰/大明杠，高于吃；吃仅下家；同优先级按距来源的座次 |
| 多家荣和 | 二家、三家均实际结算；关闭时头跳，不改为三家荣和流局 |
| 本场与供托 | 多家荣和分别支付本场，供托交距离放铳者最近的和家 |
| 无可选响应 | 自动推进；有合法响应仍需选择，过牌与见逃作为事实记录 |
| 立直 | 门清、至少 1000 点、至少 4 张活牌、弃后听牌；宣言牌未被荣和后扣棒；振听立直允许 |
| 立直后 | 仅摸切、自摸/荣和及合规暗杠；暗杠需用新摸第四枚且完整等待集合不变，不额外禁止拆分/役种变化 |
| 一发/两立直 | 从事件推导；鸣牌和杠宣言取消一发，打出立直后的下一张弃牌结束一发机会 |
| 振听 | 舍牌振听含被鸣走的舍牌；见逃至下次自己摸牌，立直后见逃本局持续；无役完成形也记录见逃 |
| 杠 | 三类杠、抢加杠、国士抢暗杠；抢杠成立不完成杠、不补牌、不翻该杠宝；第五杠禁止 |
| 王牌与杠宝 | 保持 14 张王牌，岭上补牌同时缩短活牌山；暗杠即翻，明杠/加杠在弃牌或下一次补牌前翻；岭上和前不补翻本次延迟杠宝 |
| 最后牌 | 活牌耗尽后只允许和牌响应，不再吃碰杠；海底/河底、岭上/抢杠条件交由算分适配器 |
| 途中流局 | 九种九牌由玩家声明；四风连打、四家立直、多人四杠；第四杠后先允许岭上和及弃牌荣和，一人四杠继续 |
| 荒牌 | 形式听牌，3000 点不听罚符；庄家听牌连庄；供托留存，本场加一 |
| 流局满贯 | 牌河非空、全幺九、未被鸣走；本人的副露不取消；多人逐一满贯自摸支付，不计本场/供托和不听罚符，按庄家形式听牌决定连庄 |
| 途中流局结算 | 不付不听罚符、供托留存、庄家连庄、本场加一 |
| 计分 | 不切上满贯；累计役满封顶一倍；多个役满叠加；特殊双倍役满默认关闭 |
| 包牌 | 大三元/大四喜最后成立的可见组若由他家供牌，确定责任；暗杠也计入先前可见组；只承担对应役满部分；自摸全付，第三家放铳折半，本场由责任家承担；无四杠子包牌 |
| 击飞 | 负分触发，恰好 0 点不触发；单局结果只返回标志 |

上述为本项目明确采用的基准，不宣称逐条等同于任何平台。参考[天凤四人官方规则](https://cdn.tenhou.net/man/#RULE)核对流程与规则分歧；本项目按用户确认保留三家荣和实际结算、特殊双倍役满默认关闭等选择。番符依赖固定 `mahjong==2.0.0`，配置参数以本地版本源码为准；[上游配置文档](https://mahjongrepository.github.io/mahjong/modules/hand_calculating/hand_config.html)当前显示较新版本，不据此升级依赖。

## 代码与接口

| 文件 | 职责 |
| --- | --- |
| rules/config.py | RuleConfig，模拟与分析共享规则 |
| rules/discards.py | 共享弃牌限制；从完整可见历史确认弃牌许可 |
| simulation/engine.py | Simulator：牌山、动作验证、响应裁决、阶段推进 |
| simulation/settlement.py | 和牌、包牌、流局支付与下一局元数据 |
| simulation/observation.py | 每个事实时点投影四份互相隔离的玩家观察记录 |
| simulation/persistence.py | 全知初始状态＋提交动作的保存与确定性重放 |
| processing/observed_simulation.py | 应用已确认可见变化，不导入模拟器或执行规则裁决 |
| simulator_ui/ | 新的独立单窗口测试工具；原 test_ui 与 event_ui 保持用途 |

```python
Simulator(*, rules=None, seed=None, wall=None, dealer=0, round_wind="east",
          hand_number=1, honba=0, sticks=0, scores=None, round_id=None)
game.legal_actions(seat)          # 仅该玩家当前合法 Action；没有待选择动作则为空
game.submit(action)               # 校验并原子执行；非法动作 ValueError，原状态不变
game.observe(seat)                # 独立的 RoundSnapshot 副本
game.record(seat)                 # 独立的玩家 RoundRecord 副本
game.result                      # 结束后支付/番符/连庄/下一局场况，否则 None
game.version                     # 成功动作后的新修订标识
game.command_count               # 已提交动作数量
game.debug_state()               # 明确全知调试出口，禁止作为分析输入
```

固定 `wall` 为完整 136 张牌码序列，主要用于可复现规则测试；随机开局可传 seed。实现按固定区段配牌，不模拟掷骰或实体牌墙动画。非法操作不会变成成功事件，也不实行错和罚分。

`save_simulation(game, path)` / `load_simulation(path)` 使用 `nanikiru-simulation-v1`：保存真实初始牌序、规则、场况和动作。加载逐步验证全部动作，非法文件不能替换 UI 的当前局。`replay_simulation(game, through)` 的 through 是提交动作数；省略表示全部，0 仍包含开局自动首摸。

## 可见事件与分析输入

模拟器保存全知事实用于内部推导；立直、一发、见逃等从事实查询，没有加入可修改的 PlayerInfo 资格字段。四份观察记录是可从全知存档重建的输出，不是第二个推进权威。

每个 `sim_*` 观察事件包含 `fact`（可见行为）与 `changes`（该时点可见状态变化）。变化复用现有五种数据结构：牌表、玩家点数/暗手数量、组、阶段、响应等。processing 仅应用变化和检查结构，不再次执行动作。事件种类包括 draw、discard、kan_declared、chi、pon、三类杠、riichi_accepted、本人 pass/response、ended。

对手暗摸不带实体 ID 或牌面；其他玩家的未决选择及过牌事件不进入本人的记录。因私有事件不同，四份记录的本地事件编号不一定相同，pending 引用转换为各自编号。UI 显示的是所选玩家的可见事件序号，不冒称全知动作序号。

杠宣言尚未成立时，观察牌表以 `declared` 区域表示他家已经公开的待裁决牌，避免误记为成立副露或漏算可见库存；本方牌仍留在自己的手牌中。终局只在终局事件公开赢家手牌与适用里宝，过去时点不被回写；未和玩家暗手不自动公开。

```text
Simulator.record(seat)
  → build_analysis_request(record, source_version=game.version, through=可见事件数量)
  → analyze(request)
  → 统一结果
```

完整模拟观察可确认立直摸切与食替约束，分析候选据此标 allowed/forbidden，最小牌效推荐只选 allowed。缺历史的人工记录仍保留 unknown 与条件偏好。当前只新增弃牌许可共享查询，不宣称分析调度器已支持吃碰杠比较、实际和牌许可任务或综合攻防策略。

`RoundSnapshot.rules` 携带配置；`score_hand(..., rules=position.rules)` 和底层 evaluate 使用同一套算分开关。不传配置时也采用当前默认（特殊双倍役满关闭），旧的显式 aka_dora_enabled 参数仅在没有 rules 时生效。最小牌效只比较形状与进张，开关对无关的牌形数值不产生伪影响。

## 验证

单元测试覆盖规则开关、动作原子性、视角隔离、吃碰竞争、三类杠、国士抢暗杠、加杠被抢、立直及见逃、一人/多人四杠、四家立直、四风连打、九种九牌、三家荣和及头跳、供托/本场、荒牌/流局满贯、包牌部分支付、完整回放与保存加载。每次成功提交检查 136 张实体库存和点数＋供托守恒。部分结算边界以隔离的规则单测验证，不冒充完整实战序列。

另运行 8 局固定种子的连续动作检查，包含 634 次弃牌、26 次碰、53 次吃、4 次加杠，均正常结束。随机测试驱动不是强策略，也不能证明所有麻将组合已穷尽。当前共 95 项测试通过；新增 26 项模拟器测试。新 UI 交互与截图检查覆盖紧凑/展开布局、大明杠、四副露和结算；两个既有工具的交互回归通过。
