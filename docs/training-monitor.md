# 训练进度窗口与事件规范化

更新：2026-11-14。

## 查看进度

```powershell
.\.venv\Scripts\python.exe -m training_ui
# 指定其他实验目录
.\.venv\Scripts\python.exe -m training_ui data/external-replays/my-round1
```

也可运行项目根目录 `run_training_ui.py`。窗口每两秒读取一次文件，关闭窗口不会停止计算。原单局面、模拟器和事件 UI 不变。

- 预处理：显示每个分片的导入场数、已计算特征数、状态、更新时间和错误；完成数量从各分片 manifest 汇总，不信任旧总计数。
- 拟合：显示轮次、当前参数、试值、训练损失；曲线显示默认参数和每轮结束的训练／验证损失。它是坐标搜索，不是神经网络 epoch；损失不是和牌率。
- 测试：拟合完成并选定参数后才进入最终评测；不展示用于反复选参的测试损失曲线。
- 旧任务缺少心跳或中间指标时明确显示未记录；不伪造曲线、百分比或预计完成时间。40 批进度只代表预处理，不代表整个实验。
- 本窗口只读，不启动/停止任务，不跳过代码指纹校验，也不把文件更新时间当作进程存活证明。

## 新任务的进度文件

`examples.train_v2_round1` 新运行会生成：

- `status.json`：每两秒协调器状态、完成批数、失败列表、剩余任务数；失败分片立即显示，其他任务继续独立完成。存在失败时禁止合并和拟合。
- `chunk-NNN.json`：工作进程自己的阶段、导入场数、特征行数、错误和更新时间；导入每场更新，特征每 100 条更新。
- `fit-progress.jsonl`：默认损失、每个权重试值的开始/完成、每轮损失和参数、最终评测阶段。

核心接口的可选 progress 回调仅报告状态，不改变权重搜索、候选或数据划分；测试确认启用/关闭回调的拟合结果一致，选参仍不读测试集。直接调用核心接口时需传入 progress 才能收到中间进度；上述实验入口已经接好文件写入。

## 四家立直缺失事件

模拟器已实现四家立直流局。分析器负责基于可见事实提出候选，不负责从原始牌谱补事件；导入器也不调用模拟器重裁来源。

此前失败的 MJAI 文件省略了第四次 reach_accepted，导致跨局点数检查失败。适配器新增有限规范化：在途中流局规则开启、三家已立直成立、唯一第四家已声明并打出宣言牌、紧接零支付 ryukyoku、且没有冲突流局原因时，按四家立直终局补入第四家成立、扣棒、增加供托。标记 normalization，流局原因为 four_riichi。

该推导只发生在已看到当前流局事件时，不借用下一局信息回写之前的决策输入。下一局点数仍独立校验，其他矛盾仍拒绝。明确给出第四次成立时不重复扣棒。

真实失败样本已验证可完整导入：10 局、482 个决策；新增测试覆盖补齐、明确成立不重复、过去输入无泄漏、下一局矛盾仍拒绝。
