## 选择依据与来源

- 官方规则：<https://cdn.tenhou.net/man/#RULE>，段位战四人及役种补充部分。
- 语料：<https://huggingface.co/datasets/nikketryhard/tenhou-houou-mjai>，已固定下载版本见 mjai-adapter.md。
- 本地 `tenhou-houou-2026.tar` 全部 12,188 个对局文件名都是 `00a9 / 0000`：四人、食断、赤牌、半庄、凤凰桌、段位战大厅。该计数只证明来源标记覆盖，不是完整事件逐局审计或数据授权证明。
- 首批正式规则检查限制为 2023 年及以后的相同标记，避开已知旧年度规则变化。年度、房间信息来自来源文件名；MJAI 本身不能证明这些规则。重命名文件不能成为合法的来源核对手段。

## 代码中的规则边界

`rules/config.py::tenhou_hanchan()` 返回完整不可变配置；传入模拟器后随观察和分析请求保存。无参数 `RuleConfig()` 和 `Simulator()` 保留旧自定义规则，不静默改变既有实验。模拟器窗口可选择“天凤四人半庄”，随后点击“新建单局”；更改其中的开关后属于自定义变体。

本轮核对后新增的差异处理：

| 项目 | 天凤目标配置与实现 |
| --- | --- |
| 三家荣和 | 流局、连庄，供托留存；旧自定义仍可三家实际结算 |
| 双荣和本场 | 本场和供托仅最近和家取得；两家的和牌本体支付分别计算 |
| 抢暗杠 | 不允许国士抢暗杠，模拟裁决与分析候选一致 |
| 加杠一发 | 首次加杠被抢时不提前取消一发；完成加杠后取消，连续杠不能重复保留 |
| 包牌 | 大三元/大四喜包牌覆盖其复合役满总额；自摸全付、他家放铳折半，本场由包家承担 |
| 形式听牌 | 允许副露牌造成的第五枚等待，但纯手牌已有四枚不成立；与实际实体进张分开 |
| 半庄结束 | 负分击飞；南四及以后庄家达标首位和了止/听牌止；西入及上限；同点按起家顺序 |
| 终局供托和分数 | 余棒交首位，25000 起、30000 返、10–20 顺位马与首位返还差额，不作千点四舍五入 |

已核对且继续复用的部分：每门一赤、后付、食替限制、门清立直与最低点数/剩余摸牌要求、等待不变且必须使用新摸第四张的立直暗杠、暗杠即时宝牌与明/加杠延迟宝牌、海底禁鸣、特殊双倍役满关闭、多个役满叠加、累计役满、连风四符、流局满贯替代不听罚符和按庄家听牌决定连庄。自动化检查不是所有组合的穷举证明。

`waits(..., formal=True)` 仅扩展形式等待定义，不增加未见牌数量。基础分析的等待牌列表仍表示实际牌形等待，附带 `details.formal_tenpai`；因此可能列表为空而形式听牌为真。不能据此宣称存在实际和牌进张。

`rules/match.py::match_status` 是纯场况判断；模拟器终局结果增加 `match`，包含是否整场结束、原因和顺位，结束时还包含最终供托和按顺位排列的结算分。`next_round` 保留用于回顾，`match.ended=true` 时不得据它自动续局。没有增加自动多局调度。已有 v2 仍不支持名次目标优化，规则适配不等于学会南四保位或最优避四策略；`match_rank` 请求仍明确拒绝。

## 导入与训练规则检查

```powershell
.\.venv\Scripts\python.exe -m nanikiru.adapters.mjai data/external-replays/huggingface/tenhou-houou-2026.tar data/external-replays/my-tenhou-import --profile tenhou --limit 10 --samples-per-game 12
.\.venv\Scripts\python.exe -m nanikiru.training prepare data/external-replays/my-tenhou-import/discard-samples.jsonl --output data/external-replays/my-tenhou-cache
```

`--profile tenhou` 现在使用本规则配置，并检查 2023+ 的 `00a9/0000` 来源文件名和东一、零本场、零供托、四家 25000 点的完整开局。输出样本的 `rules_verification` 位于分析输入之外，保存配置版本、来源哈希、成员名和核对依据；观察器保留它。它是导入溯源记录，不是对任意外来 JSON 的真实性认证。

训练命令默认核对这一配置及来源记录，配置缺失、不符或未核对即报错。任何一次缓存都拒绝混合不同规则。旧试验样本不能靠手工修改配置继续训练，须从原谱重新导入；代码指纹变化也要求重建缓存。

`--rules-profile experimental` 显式允许尚未核对来源的单一规则实验；程序接口 `prepare(..., rules_profile=None)` 同样标记为实验。正式目标使用 `prepare(..., rules_profile=TENHOU_HANCHAN)`。实验缓存不等于标准规则语料。天凤 XML 读取现采用平台对应配置，但尚不自动提供本次严格的房间/年度来源核对记录；正式目标先走已核对的 MJAI 导出入口。雀魂及其他房间不能冒用本标识。

## 验证与限制

本轮新增回归覆盖三家荣和、双荣和本场、抢暗杠、加杠一发在模拟/分析中的一致性、形式死听、复合役满包牌、半庄结束边界、顺位供托和总分守恒、规则来源校验与观察变体传递。全套 152 项测试通过；模拟器界面自动交互检查通过（包含选择规则预设后传入分析器）。本次未改动原单局面 test_ui。

按新配置重新导入的真实小批位于 `data/external-replays/tenhou-rules-2026-pilot/`：10 场、110 局、5,235 个决策，抽取 120 条。没有修改原始归档，没有更新默认策略权重。

数据集缺失的流局原因、私有见逃等仍保留未知；按平台规则配置并不能补出缺失事实。当前训练仍仅模仿弃牌/立直，不能将其结果解释成全动作正确率、和牌率或整场实战强度。
