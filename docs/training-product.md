## 已确认的训练体验

- 随机开始四人日麻牌局，由玩家操作一家，另外三家接入训练好的机器人。
- 模型评估玩家每次弃牌的质量；切出后展示“该切评分”及判定。
- 保留本局逐切评分，汇总为整局训练评分，支持复盘。
- 继续以模型训练、数据处理、接口调用与封装为主要学习目标；桌面界面承载操作和评测。
- 摄像头监控与何切推荐作为评估系统的后续应用，保留接口方向，之后再开发视觉模型。视觉输入先雀魂画面、再手机摄像头，智能眼镜为远期方向。

当前已完成单局规则与结算，并加入基础牌效评估；连续多局沿用后续扩展方向。“整局训练评分”先对应一局牌，整场东风战的训练汇总另行确定。

## 能力边界与建议接口

先用同一 Python 项目内的函数调用，无需提前增加网络服务或模型框架。以下为总体接口方向；基础牌效的已实现 API 和统计口径见 `efficiency-review.md`，模型接口仍是建议。

1. 游戏核心维护真实状态、牌山与规则，提供指定座位的观察和合法动作，接收人工或机器人提交的动作。
2. 机器人根据自己的观察及合法动作作出决策。当前基础牌效机器人代替测试人员提交其座位的响应，核心仍收集所需响应后统一裁决；保留全人工调试方式。
3. 评估模块接收行动前的玩家观察、合法候选动作和实际选择，返回候选评价、所选动作评分与判定。切牌推荐复用候选评价结果。
4. 训练记录保存决策对应的局与动作编号、行动前观察、所选动作、模型版本及评估结果；与牌局事实和番符结算分开。
5. 界面在合法弃牌成功后展示对应评分，局终展示逐切记录和汇总。未接入模型或评估失败应明确标记“未评分”，不能填零冒充低分。

评分和机器人输入不得包含全知状态、种子、对手暗手或后续摸牌。展示发生在弃牌之后，但评估依据应固定在弃牌之前；不可因看到后来摸到什么而倒推这一切的质量。全知调试信息保持独立。

模型推测不写成牌局事实。策略模型用于选择动作，评分模型用于评价决策，两者可以共享模型，也可以分别实现，不预先强制绑定。撤销、回放或重新评估时必须关联正确动作及模型版本，避免旧评分附着到新分支。

## 两种分数必须分开

- 麻将结算点数：由规则确定，包括役、番、符、支付、立直棒与本场等。
- 训练决策评分：模型对当时决策质量的评价，不修改麻将点数，也不等同于实际输赢。

逐切评分的量纲、判定阈值和整局聚合算法尚未确认。可评估与最优候选的价值差、归一化评分等方案；不能把模仿模型的选牌概率直接当作客观正确率。整局汇总也不能未经确认直接累加，让出牌次数影响可比性。模型评价本身需要基准牌例和独立测试集验证。

## 建议实施顺序与验收

1. 完成响应、吃碰杠、立直、和牌、流局及单局结算，详见 `rules-and-settlement.md`。验收：规则案例、库存守恒、保存回放与非法操作介入流程通过。
2. 增加随机开局入口并保留显式种子与完整牌山存档；接入简单基准机器人，作为模型接入前的测试工具。验收：一家人工与三家自动策略能够完成合法单局，且策略无法读取隐藏信息。
3. 明确评分定义，先建立可复现的基准评估与逐切记录、切后展示、整局汇总闭环。验收：评估对应行动前观察；回放和撤销后记录一致；未评分不混入有效分数。
4. 整理牌谱并训练、评测和接入模型，逐步替换基准策略及评估。按完整牌局划分训练与测试数据，记录模型版本；完整机器人还需能处理切牌之外的合法响应。
5. 用共享评估入口支持外部局面与何切推荐，再增加视觉输入转换和手机接口。外部观察不完整时保留未知，不伪造完整牌山。

当前已实现随机/种子开局、玩家观察、图形牌桌、理牌，以及四家人工操作的响应、吃碰杠、立直、和牌、流局与单局结算。具体基准见 `rules-and-settlement.md`。基础牌效候选比较、切后展示、逐切保存回放和整局汇总已实现，详见 `efficiency-review.md`。同向听比较进张，不采用百分制；不代表综合最优决策。已接入三家基础牌效自动对手；模型评分及连续多局调度仍未实现。

## 基础牌效机器人（2026-09-16）

下拉菜单卡住修复：Tk 自建的 `popdown` 没有 Python 控件包装，调用 `grab_current()` 会触发 `KeyError`。改为直接查询 Tcl 的抓取窗口是否存在；菜单展开时等待，关闭后继续机器人动作。定时循环提前登记下一次调用，避免异常导致永久停轮询。新增真实 ttk 弹出窗口回归，修复前复现相同异常，修复后全部 12 项界面测试通过。

策略入口 `bot.choose_action(observation, legal_actions)` 仅接收自身观察与合法动作。优先接受合法自摸/荣和；否则选基础牌效排序第一的合法弃牌；其余响应过，不主动鸣牌、杠、立直或九种九牌。并列选择固定，不代表打点或防守更优。

UI 默认人工座位和主视角为实际庄家，不硬编码座位 0；机器人运行不改变观察视角，人工响应必须显式提交。可关闭“三家机器人”回到全人工测试。回放、暂停、测试执行期间不推进；加载、撤销、回退重录后先暂停，再显式恢复。机器人开关是会话设置，实际动作与逐切记录仍使用现有 v3 存档。

验证：完整回归套件 71 项通过；最后补充真实庄家初始化/加载测试并调整界面提示后，机器人 3 项与界面 11 项定向回归全部通过。包括最优候选与隐藏信息独立性、合法自摸/荣和及过、三家机器人配合人工动作完成单局、存档记录一致性、主视角保持，以及暂停/回放/撤销时停止推进。实际检查截图 `ui-checks/bots-table.png`，庄家为玩家 2，机器人推进后视角仍保持玩家 2。
