# 牌谱适配器事件检查（2026-11-14）

适配器校验来源事件的一致性，输出四家独立可见记录；不调用模拟器重新裁定牌谱中的役种、振听或最终点数。修复某种来源省略，必须有明确触发条件，不能把任意不完整牌谱自动补成完整历史。

## 本次加固

| 接口/事件 | 约束 |
| --- | --- |
| MJAI 开局、牌码、鸣牌参数 | JSON 行须为对象；四家 13 张手牌；牌码为字符串；本场/供托为非负整数；consumed 为列表 |
| 摸打与副露 | 检查阶段、行动者、实体牌库存、手牌张数及副露形状；暗杠/加杠必须在自己的摸牌后发生 |
| 立直 | 宣言、弃牌、成立顺序一致；下一次摸牌或鸣牌前不能仍缺成立；重复成立或不足 1000 点拒绝；双立直由首巡及未发生副露推导 |
| 四家立直省略 | MJAI 按已记录的严格终局条件补齐第四次成立；XML 在明确 reach4、三人成立且第四人刚宣言弃牌时补齐，再检查终局分数基线 |
| 立直宣言牌被荣和 | 不补立直成立，不扣供托 |
| 杠与宝牌 | 未开杠不能新增杠宝；支持延迟翻宝；抢杠不提交被抢的杠 |
| 自摸、荣和、多家荣和 | 和牌对象匹配当前摸牌/响应；不重复赢家、不混合不同放铳者、不在流局后追加和牌 |
| 终局与跨局 | XML 结算基线必须等于此前事件累计点数；点数加供托守恒；下一局点数和供托均须衔接 |
| MJAI 导出 | 出错仍保留 incomplete 报告，增加具体成员名与错误；不跳过错误后把残缺结果标为成功 |
| 压缩与 tar | 继续按魔数解压、不解包成员路径；补充 jsonl/mjson 的 gzip/zstd 成员后缀 |

未知流局原因继续保持未知。九种九牌、四风连打、四杠散了、三家荣和等来源终局信息可传递，但本次没有新增“从缺失事件猜测所有流局原因”的逻辑。
