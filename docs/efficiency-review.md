## 输入与计算

`nanikiru/efficiency.py` 独立于 UI、Game 和算分模块，仅接收行动前 `Game.observe(seat)` 的观察与该玩家合法 `Discard` 列表。合法性由游戏核心负责（包括立直和食替约束），分析模块不推断额外合法动作。拒绝全知观察和包含对手暗手的输入。

复用固定依赖 `mahjong==2.0.0` 的 Shanten。逐候选移除弃牌，计算普通形向听；没有副露时同时考虑七对子、国士。有暗杠也不能走这两种特殊形。枚举加入一张后降低向听的牌，得到有效进张。排序先最低向听，再最多有效进张未见枚数；两项相同全部并列最优。牌码顺序仅用于稳定显示，不打破评价并列。

未见枚数为每种牌四张减去行动前可见数量：自己暗手及摸牌、各家未被鸣走的河牌、全部副露实体牌、公开宝牌指示牌。被鸣走的河牌只在副露中计一次；杠计四张。本次拟弃牌仍属于已见牌，不能因从手牌移除而回到未见池。赤五与普通五合并计算牌形和库存，但候选保留赤牌身份。未见牌可能在对手手中或王牌中，不等于真实活牌山余量。有效进张不承诺有役或可荣和，也不评价振听影响。

## 记录、回放与统计

弃牌（含立直宣言中的弃牌）成功时，Game 同时提交对应记录：动作编号、座位、行动前观察、实际动作、候选分析及分析版本、选择比较。计算使用提交前观察，不能读取后续摸牌。动作或分析失败均不部分提交状态与记录，保留原局面并暂停显示错误；不会填零充当评价。

- `Game.review_records(seat)` 返回该玩家记录副本；`debug_reviews()` 明确为全知调试入口。不要将 Game 本体或全知存档交给未来策略。
- `analyze_discards(observation, legal_discards)` 返回候选；`compare_discard(analysis, actual)` 返回比较；`summarize_reviews(records)` 返回汇总。
- `replay(count)` 只保留该动作位置以前的记录；撤销/回退同步删除未来记录，新分支重新分析。普通回放使用已保存结果，不借用未来观察。
- 分析版本为 `basic-efficiency-v1-mahjong-2.0.0`。Game 存档升级 v3；加载按原始动作重建并核对记录、版本和候选，拒绝不一致或不支持版本。v2 仍可加载，按当前算法补建记录，下次保存为 v3；不会自动改写原文件。旧 Game v1 仍拒绝，旧 Recorder 不变。

整局统计按玩家分别计算；未结束和历史回放时只统计当前位置以前的弃牌：

| 指标 | 定义 |
| --- | --- |
| 基础牌效最优占比 | 选择最优/并列最优的次数 ÷ 有多个弃牌选择的次数 |
| 增加向听次数 | 所选切后向听高于合法候选最低向听的次数，不是与摸牌前向听比较 |
| 同向听进张损失 | 仅所选保持最低向听时，最优进张数减去所选进张数；返回总量、均值及样本数 |
| 强制选择 | 仅一种合法弃牌的局面单独计数，不进入上述质量统计分母 |

同牌面的手切和摸切保留两个动作身份，但视为一种弃牌选择；赤五与普通五仍为不同牌面。没有统计分母时返回 `None`，界面显示“不适用”。立直宣言的记录只评价弃哪张，不评价是否立直。

## 界面与验证

运行 `run_game.py`，合法弃牌后底部显示本次反馈；“逐切复盘”页显示候选、黄色实际选择、行动前手牌、版本及汇总，可选择记录或点上一切/下一切。玩家视角只显示该玩家记录，全知调试可查看四家。顶部保存、加载及底部动作回放继续适用。

`tests/test_efficiency.py` 覆盖普通形、特殊形、副露/暗杠、赤牌、鸣走河牌、指示牌、当前弃牌不回流、隐藏信息隔离、并列与统计分母，以及撤销/分支/立直/存档核对。界面测试覆盖切后反馈、实际选择高亮、视角隔离和回放撤销。截图见 `ui-checks/efficiency-review.png`。

本轮实际验证：Python 3.11.4 下完整 unittest 套件 67 项通过。加载已有 `examples/exhaustive-game.json` 的 280 动作荒牌对局，补建 70 条弃牌分析，四家分别为 18、18、17、17 条；回放至初始位置记录为空。1100×820 窗口截图已检查，表格具备横纵滚动条，切后反馈与回放操作可见。
