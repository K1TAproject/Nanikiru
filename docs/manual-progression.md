# 人工事件推进：最小闭环

更新：2026-11-11。已实现可见事实的摸打记录、响应结束、撤销、保存加载和回放。不是随机对战模拟器，也不是完整合法动作或结算引擎。独立界面见 [event_ui 操作说明](../event_ui/README.md)；原 `test_ui/` 单局面工具保持不变。

## 结构与权威数据

- `processing/events.py`：四种事件的严格载荷校验。
- `processing/progression.py`：`apply_event(position, event) -> new_position`，检查阶段、玩家、引用、已知数量、库存及摸切一致性后生成新快照。
- `processing/records.py`：记录追加、重建、撤销、文件格式和 Session 版本管理。
- `event_ui/`：人工输入、图形手牌/牌河、历史回放、基础分析展示；不实现核心状态变更。

继续使用五种基础结构。权威信息只有 `RoundRecord.initial_snapshot + events + coverage`，当前局面由其重建。Session 内的快照是派生缓存；对外取 record/position 返回副本。失败的操作不改变记录、快照或版本。

## 事件清单

所有事件具有正整数 id，记录中唯一递增。target_id 用于引用响应对象，data 不允许夹带未定义字段。`UNKNOWN` 必须传枚举对象，不能用字符串替代。

| kind | actor / target_id | data | 作用 |
| --- | --- | --- | --- |
| draw | 明确玩家 / None | tile_id、code | 普通摸牌，待摸牌 → 待弃牌 |
| discard | 明确玩家 / None | tile_id、code、discard_kind | 暗手转入牌河，待弃牌 → 待响应，主动 actor 置 None |
| close_response | None / 当前触发事件 id | 空字典 | 人工确认本次无鸣牌/无和牌，待响应 → 下家待摸牌 |
| halt | None / None | reason | 记录未支持情况；phase 置 UNKNOWN、actor 置 None，保留已有牌及响应上下文 |

### 摸牌与弃牌

自己摸牌：提供新 tile_id 和牌码，牌面不明可传 UNKNOWN，占位牌仍只算一张。对手暗摸：强制 `tile_id=None, code=UNKNOWN`，只增加未建档暗手数量，不允许录入隐藏牌面或身份。已知剩余摸牌数减一；原为 UNKNOWN 则继续未知。已知余牌为零时拒绝继续摸牌，不自动生成流局结算。

弃牌：已建档暗手引用原 tile_id，原牌面已知时不得改写；原牌面未知可由本次公开确认。未建档暗手公开时使用新 tile_id，减少未建档数量；数量未知则仍为 UNKNOWN，不能当作零。任何情况下同一实体只有一条牌记录。

`discard_kind` 为 hand、tsumogiri 或 UNKNOWN。已有明确摸牌身份时，矛盾标记被拒绝；未知上下文不能用来推断方式。只要确知各家数量和组覆盖，就检查相应 13/14 张等价数量。已知实体库存仍遵循每门一赤、普通五三枚等约束。

### 响应与停止

弃牌后必须保留响应窗口。`close_response` 必须指向当前弃牌，已知响应包含吃碰杠/和牌时不能当作无响应关闭。关闭后不补造逐家 pass、不推导临时振听或立直振听；它仅表示观察到的窗口结束结果。

中途从响应窗口接入时，若接入前事件编号不存在，初始 pending.trigger_event 和本次 target_id 均用 UNKNOWN；来源玩家与当前弃牌必须已知且一致。

halt.reason 为 chi/pon/kan/riichi/win/draw_end/other。它记录“此处遇到未实现动作，已停止”，不代表该动作已经应用。不能用 close_response 跳过吃碰杠或和牌。撤销 halt 可恢复暂停前状态；仅应在更正误录时这样做，真实未支持动作需要后续功能或从确认后的新快照接入。

## 记录接口与版本

| 接口 | 行为 |
| --- | --- |
| replay(record, through=None) | 重建前 N 条事件；0 是初始快照，None 是末尾 |
| append_event(record, event) | 验证全部已有记录及新事件，返回新记录；拒绝重复/倒序 id |
| undo(record) | 删除最后一条事件并验证可重建；空记录报错 |
| save_record(record, path) | 验证完整回放，写同目录临时文件后原子替换 |
| load_record(path) | 解码并验证全部事件，成功才返回记录 |
| Session(record) | 持有记录、派生当前快照和 state_version |
| Session.append(kind, actor=..., target_id=..., data=...) | 分配下一事件编号，成功后替换当前记录 |
| Session.undo() / load(path) / save(path) | 撤销、加载、保存；加载失败保留旧状态 |

每次成功追加、撤销或加载生成新的 state_version，包括撤销后分支或加载同一记录；失败操作不改变版本。UI 每次重算分析，回放视图再附加事件步数，避免复用不同时间点的旧结果。没有异步后台分析缓存。

回放是只读视图，不把 Session 的当前记录截断。需要修改历史时，先回到最新并逐步撤销，再重新录入。当前不提供任意中间事件替换和自动修复后续事件。

## 文件与中途接入

外层格式为 `nanikiru-manual-v1`，内层记录仍标识 observation-v1。文件只保存初始快照、事件和覆盖信息；不保存第二份“当前状态”、真实牌山、随机种子或分析结果。

未知使用专用 JSON 对象 `{"$unknown": true}`，加载后恢复同一个 UNKNOWN 枚举；None 使用 null，不与未知混淆。`$unknown` 是保留键。玩家/牌/事件序列恢复成规定结构，pending.responses 的座位键恢复为整数。扩展上下文使用 JSON 兼容数据。

不兼容旧 Game/Recorder JSON，不会自动迁移历史样例。文件写入失败会清理本次临时文件，不先截断旧文件。UI 默认禁止覆盖已存在路径，需用户勾选允许覆盖。

中途接入从已确认的当前快照开始，coverage.from_start=False；已有各家牌河只保留各自顺序，不补造接入前的全局事件顺序。缺失的公开牌覆盖继续标不完整，后续几次正常摸打不会把它变成完整。当前不跨 coverage.gaps 推演：遇到非空缺口列表会拒绝连续回放，应从缺口后的确认快照另建中途记录。

UI 的中途创建器只支持无副露、自己 13 张或本人待弃牌时 14 张、其他家 13/14 张的明确假设。更复杂的初始结构可以通过核心数据接口表达，但缺少阶段/来源等必要事实时仍会拒绝相应推进。不声称支持任意未知局面的自动恢复。

## 验证与边界

当前 58 项单元测试通过，其中推进新增 17 项：一轮摸打重建、重复与错序、错误不污染数据、未知牌揭示、私有信息拒绝、响应确认、撤销分支、版本、保存加载、暂停、余牌为零及中途接入等。独立 `event_ui.smoke` 检查两种尺寸、按钮录入一轮、保存加载、只读回放、撤销、暂停和中途创建。

仍未实现吃碰杠应用、立直成立、资格历史推导、响应竞争裁决、和牌/流局结算、任意历史修订、视觉识别纠错或多局比赛推进。状态相容检查不等于完整合法性判断，未知资格不变成允许操作的证明。

补充视觉验收（2026-11-11，桌面解锁后）：已实际查看 1260×900 与 1180×760 窗口的截图，覆盖初始局面、一轮摸打、只读回放、中途接入、暂停及长牌河滚动。手牌、独立摸牌、指示牌、牌河、历史与分析区均可同时显示，无互相遮挡；长牌河可滚动到最后一行，返回最新时可见当前事件；回放/暂停时推进按钮正确禁用。独立 event_ui.smoke 再次通过。未发现需要修改代码的界面问题，原单局面 UI 仍未改动。本次结论限于所检查窗口尺寸及当前系统显示环境。
