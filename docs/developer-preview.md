# 开发者预览版

本阶段交付单局训练闭环：三家基准机器人、合法特殊动作与结算、弃牌反馈、听牌比较、一向听推进、基础立直比较及讲解停顿。不是完整最优策略、全部日麻规则变体或商业发行版；不包含模型、综合评分、自动攻守、主动杠策略、多局调度或视觉输入。

## 启动与入口

从项目根目录运行 `.\.venv\Scripts\python.exe run_game.py`。依赖仍为 Python 3.11+、Tkinter 和固定 `mahjong==2.0.0`，没有新增运行依赖。

- 默认庄家人工、庄家主视角，另外三家使用“基础立直”。设置内可切换“役种感知”或“基础牌效”，保留旧策略行为。进攻／弃和只作用于支持这些模式的策略，基础牌效仍禁用该设置。
- 牌桌反馈区“推进／立直”：自己待弃牌时显示当前合法立直动作的条件比较；其他时间可从历史记录查看。比较本身不提交动作。实际立直仍在下方合法动作菜单选择“立直 某牌（手切／摸切）”并执行。
- 推进页选择历史动作、候选弃牌，点“分析一向听推进”，再依次选择假设摸牌、下一次弃牌。只有一向听候选适用，不适用或受限有明确提示。番符与支付默认收起。
- 原“候选比较”保留实际弃牌与另一候选的并排比较，页内“推进／立直”可带入当前选中的历史候选。新页面不改变原基础牌效最优、同向听进张损失或防守口径。
- 设置中的“仅有过时自动响应”默认开启，可关闭恢复逐家人工调试。启用时有任何合法吃、碰、杠、荣和等机会仍交给人工选择。机器人策略自行选择响应，来源不冒充人工。
- “人工弃牌后等待继续”默认关闭；开启后含立直宣言弃牌也先停下讲解。继续仅释放讲解停顿，不解除核心暂停或非法动作介入。
- 四家手牌为连续单行，侧家为竖向单列；摸入牌独立留间距。长牌河压缩行距，保留顺序、立直和鸣走标记。全知调试仍独立、醒目标记；普通视角不读取暗牌来驱动牌面。

## 一向听推进接口与边界

`nanikiru.progression.analyze_progression(observation, legal_discards)` 接收玩家行动前观察和核心合法弃牌，返回 `one-shanten-progression-v1`。

输出 `candidates` 中各项含初始 `discard`、适用状态及 `draws`。每个摸牌项包含实体牌码（含赤五）、未见枚数、`branches`（下一次合法弃牌的完整听牌分析）、限制标记和假设。分支保留原听牌模块的等待、普通荣和／自摸、有役条件、振听和条件番符支付。不排序综合优劣，不计算概率或期望收益。

库存采用共享 `efficiency.visible_inventory` 与 `physical_capacity`：赤五一张、普通五三张，其余四张。自家手牌、公开副露、未被鸣走河牌和指示牌只计一次。初始弃牌移入自己的假设牌河；假设摸牌变为已见，后续弃牌不回流未见。牌形仍合并赤五与普通五。共享 `discard_rules.validate_discard` 由核心和投影共同使用，保留实体牌及摸切／手切身份。

条件是假设期间公开信息不变，不预测对手行动。自己的下一次普通摸牌解除临时振听；未知／已有立直后振听保留，完整等待集合与自己的全部牌河重新判断舍牌振听。初始食替由传入合法动作保证；自己下次摸牌不沿用上一次吃碰的食替限制。没有完整隐藏 Game 克隆。活牌山不足一巡或矛盾的已立直一向听状态标受限；不假设鸣牌改变顺序。

普通形、七对子和国士沿用已有库的适用条件。只枚举降低一向听的有效摸牌和进入听牌的后续弃牌，不搜索维持向听改良、第二次摸牌或假设鸣牌。

## 立直比较与机器人基准

`nanikiru.riichi_decision.analyze_riichi(observation, legal_actions, mode="attack")` 返回 `riichi-conservative-v1`，每行是同一实体牌、同一摸切／手切来源的普通弃牌与核心合法立直动作。保存默听和假设立直成立两套听牌结果、1000 点支出、明确威胁、推荐布尔值与理由。

比较只使用公开场风、自风、规则、指示牌及自己的振听信息。`observe(seat).riichi_context.double_eligible` 来自核心共享的未中断首次弃牌条件，表示条件资格，不是立直已经成立。未知资格只按普通立直条件展示并说明受限。宣言被荣和时不提前扣棒、也不提前写入已立直；裁决及结算仍由核心负责。

首版先用现有役种／防守策略选择弃牌，再对该弃牌的对应立直动作依次判断：

1. 合法自摸／荣和优先。
2. 弃和模式、明确对手立直威胁、振听受限／未知、宣言资格未知或等待已见尽时，不自动立直。
3. 默听的所有理论普通荣和等待均无役，而立直成立可增加尚有未见牌的有役荣和路径时，选择合法立直。
4. 默听已有役或需要比较打点与行动自由时，保守默听。

不设任意阈值，不把宝牌当作役，不擅自推测里宝、一发或对手行为。基础支付不含本场、供托、责任支付；另列立直 1000 点支出，不把条件支付减去支出称为净期望收益。成立后的行动限制仍由核心执行。

`choose_riichi_action` 只转换现有策略选中的对应弃牌，不改变旧吃碰排序、现物防守、旧机器人或基础牌效指标。一向听结果只用于解释，未接入策略权重。这是开发基准，不代表实战最优。

## 记录与兼容

新 Game 存档为 **v7**，继续支持 v2–v6；旧 Recorder v1 独立保留，Game v1 仍按原规则拒绝。

- 行动前观察增加独立 `riichi_context`。立直评价保存在原 `decision_records` 的 `riichi` 字段，引用同一记录的观察、实际动作与 `policy`，不重复保存局面。新策略的和牌动作也保留来源及决策记录。
- 新策略来源为 `riichi-conservative-v1`；人工仍 `manual`；界面自动过为 `ui-auto-pass-v1`；旧基准名称保持不变。自动过通过 `Game.submit`，逐家收集并统一裁决，每次轮询至多一个动作。
- 一向听投影可由已有行动前观察与合法候选确定性重建，不保存全部搜索树；返回独立版本及假设。历史缺少自身信息保留未知；缺少立直评价显示“未记录”，不从当前设置补猜。
- 加载根据原记录字段是否存在重建，保存后仍保持旧字段缺失，不给旧记录补造新评价。撤销、回退分支和只读回放沿用动作索引截取记录，不重写原牌效统计。

## 交互状态与性能

自动过与机器人共用非阻塞轮询入口。核心暂停、非法动作介入、讲解停顿、只读回放、测试执行、模态抓取、结束都禁止推进。仅有过设置只影响后续轮询；不清除暂停。撤销／加载沿用原核心暂停策略；讲解状态仍是 UI 会话状态，不写成麻将事实。

推进页按所选历史弃牌计算全部分支，使用后台线程和主线程队列展示；工作线程仅持有观察副本。缓存以完整观察与候选为键，最多 16 项，只淘汰缓存、不截断结果。新局、视角切换、回退导致所选记录变化时使旧任务失效；机器人和自动过不切换正在浏览的记录。计算完成不改变真实牌局或基础牌效反馈。

本机代表性测量（同进程有已热缓存，不能视为最坏耗时上限）：完整普通牌例 13 候选、60 个有效实体摸牌、73 个听牌分支约 **0.55 秒**；另一个一向听例约 **0.015 秒**，七对子例约 **0.068 秒**。因此搜索按需后台执行，牌桌刷新不运行完整搜索。原始数量与时间见 `ui-checks/preview-verification.json`。
