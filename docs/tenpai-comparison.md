# 听牌候选比较与讲解停顿

2026-09-18。本阶段仅新增已保存分析的比较和 UI 交互。没有修改基础牌效排序、役种/防守/听牌算法、机器人策略、统计、规则及 Game v6 存档。

## 比较口径

`tenpai_comparison.compare_candidates(record, alternative_discard, decision_record=None)` 比较实际弃牌与指定候选。输入是同一行动的 `review_records` 记录、其中一个 `discard` 字典，以及可选的同一行动决策记录。不是全知 Game 输入，拒绝全知观察；决策记录必须具有相同动作位置、玩家、行动前观察和实际动作，避免拼入别次防守依据。

候选必须存在于已保存的合法候选列表。`candidate_view` 从记录投影切后暗手并保留副露，从已保存分析提取基础牌效、听牌、防守及模式，不重新计算规则、役种或番符，不改变真实局面。手切/摸切与赤牌身份保留。

输出包含：

| 字段 | 含义 |
| --- | --- |
| version | 独立版本 `tenpai-comparison-v1` |
| source_version / assumptions | 原听牌分析版本和条件假设 |
| actual / alternative | 两方弃牌身份、基础指标、切后暗手、副露、听牌结果、防守及历史模式 |
| differences | 对照减实际的等待种数、未见枚数、荣和/自摸有役未见枚数差；没有风险或支付综合分 |
| messages | 指标差异、限制不同、强制/单一听牌候选等解释 |
| status | descriptive：仅描述；limited：信息不足；not_applicable：包含未听牌候选 |

仅两方都为 0 向听且保存了受支持的听牌分析时比较听牌指标。非听牌仍可查看基础牌效；旧记录缺分析、未知自身状态、双立直未知等保留受限说明。

理论等待、尚有未见的等待、有役等待、振听限制和逐张条件支付是不同维度。普通荣和、自摸分开，已见尽仍显示；赤五与普通五沿用原结果分别列示。条件有役枚数没有扣除振听，不能称为合法荣和余量。解除临时振听后的结论仍假定等待不变且无新见逃。

不合成分数，不计算最大/平均点数来比较整体价值，没有支配关系、推荐排序或综合最优标签。番符和基础支付按各等待分别展示，保留不含本场、供托、责任支付等原假设。防守单列逐家依据，未知不等于安全。

## 界面

牌桌固定反馈区增加“候选比较”，定位最近一次当前可见的人工弃牌；也可直接打开“候选比较”标签页选择历史记录。左侧固定实际选择，右侧选择合法候选，优先默认另一种可用听牌动作（若有）；这只是初始浏览选项，不是新推荐。

两侧显示切后手牌和理论等待的牌面；下方文字显示有役、无役、振听、未知及已见尽。勾选“番符与条件明细”展示役、番符、基础支付及假设。摘要和每侧说明分别可滚动，防守说明与听牌指标分开。

候选和记录选择不会改变原来保存的实际动作。机器人推进不会重置浏览选择；切换玩家、新局或回放位置会重新过滤和定位，不能泄漏此前视角的手牌。非听牌、唯一听牌牌面、强制选择和旧记录缺失均有提示。

## 讲解停顿

“设置 → 机器人”新增“人工弃牌后等待继续”，默认关闭，适用于庄家人工及全人工调试的各座位。人工普通弃牌或立直宣言弃牌成功后，动作和分析已经保存，核心处于正常的待响应状态；UI 阻止后续提交和机器人轮询，显示独立的讲解条。

点击“继续对局”只清除讲解停顿，不提交动作、不代替响应、不调用核心恢复。若核心已暂停、正在只读回放、正在测试或对局已结束，则不能继续。手动/非法暂停须使用原有显式恢复流程；恢复核心本身也不会顺带跳过讲解。所有现有 UI 动作入口，包括注册动作和选牌确认，都受讲解停顿约束。

| 操作 | 讲解状态 |
| --- | --- |
| 开关设置 | 只影响后续人工弃牌；已停住的讲解须显式继续 |
| 切换视角、浏览候选、保存 | 保留当前讲解，按视角过滤展示 |
| 只读回放 | 保留实时讲解；回放期间禁止继续，返回当前后可继续 |
| 成功撤销、回退重录 | 清除讲解；原核心暂停语义保留 |
| 新局、成功加载 | 清除旧讲解；加载后原有机器人暂停检查语义保留 |
| 取消/失败加载或撤销 | 不清除原有讲解 |

设置、讲解状态和浏览选择是会话状态，不写入麻将事实或存档。外部脚本仍可直接调用 Game，界面停顿不是新的核心规则。

## 存档与版本

不新增存档字段、不升级格式。比较结果由已保存的行动前观察、合法候选、听牌与防守结果确定性重建，并返回自身版本。原记录始终保留原义，不回写基础指标；比较视图属于当前版本的派生解释，不冒充历史上曾经保存的新推荐。后续若改变比较语义，应升级比较版本。

撤销、分支、保存加载和回放使用原记录生命周期。旧记录没有听牌分析时不补建自身历史；版本不支持时也标记受限。没有决策记录或防守字段时显示“未保存／不可用”，不假设安全或模式。

## 固定牌例与验证范围

`tests/test_tenpai_comparison.py` 包含公开观察固定牌例：

- `123万 123筒 123索 中中 45索` 摸中：切一索与五索原本各 6 枚进张；公开观察中自家曾切二索、他家切一索后，两者各 5 枚，但只有前者舍牌振听。用于比较相同基础指标与不同限制。
- 同一手牌摸中：切中等待三/六索共 7 枚，普通荣和各 2 番；切四索等待五索共 3 枚，普通五 3 番、赤五 4 番。等待更多与部分条件打点更高分别展示，不判综合优劣。
- 南场 `23万 234筒 234索 789筒 南南`，切多余九万：一万无普通荣和役但门清自摸有役，四万可有三色同顺；公开四枚一万时仍显示已见尽。

另覆盖临时振听解除条件、缺失/未知、非听牌、强制动作、红牌身份、防守记录错配、隐藏牌山/对手暗手独立性、输入不变和存档回放分支。UI 测试覆盖候选联动及保留、隐私过滤、普通弃牌/立直讲解、所有入口阻断、继续不绕过暂停、撤销/新局/加载清理等。

本阶段没有机器人新策略、立直/默听决策、两步进张、综合评分、概率或收益模型、训练、导出及连续多局。

实际验证：Python 3.11.4 下完整 110 项 unittest 测试通过（142.228 秒）；随后仅调整文字展示次序和设置页紧凑布局、补充回退清理断言，最终 20 项 UI 测试通过。实际检查了 1100×820 和 960×760 的讲解牌桌、候选明细、历史空记录及设置页，截图见 `ui-checks/comparison-*.png`。
