## 用户已确认的目标

增加完整状态和真实牌山，支持可复现的洗牌、发牌、自动摸牌和手动弃牌。界面可以切换四位玩家视角，另有明确标记的全知调试视角。游戏 UI 要清晰简洁，使用图形牌桌展示和操作，不再完全以文字形式给出局面。

项目最终仍以模型训练和接口能力为主。此阶段建立能自行推进的游戏环境，作为后续机器人与牌谱处理的基础；不是直接实现完整四人日麻所有规则。

## 状态与接口边界

- 完整状态保存四家的真实暗手、摸入牌、完整牌山及摸牌位置、保留牌区、宝牌指示牌、牌河、副露、点数、行动者和阶段。
- 真实牌山指程序内实际生成并按确定顺序消耗的牌集合，不是实体摄像头输入，也不是每次摸牌临时随机生成一个牌面。
- 玩家观察接口只返回该玩家手牌、公开牌河/副露/宝牌、点数及其他可见局况；不包含对手暗手、未公开牌山、随机种子或私有历史。
- 全知调试入口与玩家观察入口明确分开。切换视角不改变状态或消耗牌山；查看另一位玩家的信息不等于允许他越过行动顺序操作。
- 调试 UI 和未来机器人通过核心动作接口提交决策，不直接修改内部状态。种子、新局设置属于环境控制，非机器人行动参数。
- 游戏环境自己完成摸牌；人工只决定弃哪张牌。摸牌仍记录为事件，但调用者不能选择牌山下一张。
- 旧 Recorder 继续承担不完全信息的外部记录。新环境拥有完整信息，不能通过删除旧校验或把它的 unknown_count 改成真实暗手就声称完成模拟器。

## 本阶段范围与实现建议

### 1. 完整状态、洗牌和发牌

- 建立牌集合并明确赤牌库存；沿用当前每门一张赤五的实现默认，不扩展规则配置系统。
- 使用局部随机数生成器与显式种子，可按相同种子和相同实现版本重建牌山及发牌结果。
- 明确牌山方向、发牌顺序、保留牌区与初始指示牌位置；这些为实现时需要写明的技术约定，不暗示已逐项复刻雀魂的内部洗牌算法。
- 在完整牌山上发牌，发完后由环境完成庄家的首摸，进入待弃牌阶段。
- 剩余可摸数量按牌山实际余量计算；原快照推导公式仍用于旧记录器。
- 跨版本精确重放不能仅依赖种子：设计保存格式时记录初始牌山/状态与必要版本信息，勿承诺任意运行时版本下种子行为完全一致。

验收：同种子同版本同结果；发牌、牌山、保留区的总牌库存守恒，赤牌数量正确；无额外生成或丢失的牌。

### 2. 自动摸牌与手动弃牌

- 玩家轮到行动时点击自己的牌进行弃牌；环境从牌山为下一家摸牌，并等待下一次手动弃牌。
- 自家摸入牌单独展示，原手牌与摸入牌即使同牌也能区分选择来源。
- 每次决策完整校验后再提交；非法操作不部分推进牌山、不写入半次事件。
- 保留暂停能力；最后一摸仍允许弃牌，之后结束当前摸打流程。当前不做流局结算。
- 本阶段未加入鸣牌等响应规则时，普通弃牌后直接推进到下一家摸牌；此为显式简化边界，后续引入响应阶段时调整。

验收：按序走完一局普通摸打，所有牌来自初始牌山；非行动者不能弃牌；失败操作、暂停和界面刷新均不消耗牌。

### 3. 玩家观察与全知调试

- 提供四位玩家的观察结果；视角切换后只有该玩家暗手公开，其他暗手显示牌背/未知数量。
- 全知模式持续展示醒目的“全知调试”标记，显示四家真实手牌；未公开牌山可在独立调试区检查，不要求把整副牌山铺满主画面。
- 玩家视角的日志、JSON、历史回放也必须经过过滤，不能只隐藏牌面图像而泄漏底层数据。
- 观察结果不得提供可修改内部状态的引用；切换视角或全知开关不改变给未来机器人使用的观察接口。

验收：仅改变对手暗手/未来牌山，保持玩家自己的牌与公开信息一致时，该玩家观察结果相同；全知信息不进入玩家接口；四个视角的公共信息一致。

### 4. 图形 UI

用户要求：清晰简洁、有可辨认的牌面与空间布局；文字是辅助，不是主牌桌。

建议布局与交互：

- 中央为牌桌，四家分布四边，各有手牌区、牌河区、副露区和玩家状态标记。
- 玩家视角将所选玩家置于下方，其他暗手以牌背表示；显示座位编号和自风，避免旋转布局后身份混淆。
- 手牌用独立牌块表示，牌面能区分万筒索和字牌、普通五与赤五；不依赖用户输入牌码完成常规弃牌。
- 单独间隔显示摸入牌，突出当前行动者和选中牌；建议先选牌再确认弃牌，避免误触。
- 中央显示局况、剩余牌数和宝牌指示牌；顶部提供新局、视角切换、全知调试和暂停操作。
- 牌河按顺序分行，不重叠；为未来副露、立直宣言牌和特殊动作区留出明确位置。
- 操作日志、状态 JSON 和自动化测试输出放在侧栏或独立标签页，继续保留已有调试用途。
- 不要求复杂动画、联网、账户或完整商业游戏外观。可以先评估现有 Tk Canvas/控件是否足够，不预先更换框架或安装新依赖。

验收：实际打开并检查四种玩家视角和全知模式；手牌、摸入牌、河牌及当前行动者清楚可辨；点击弃牌后牌桌及时更新；窗口调整大小和合理显示缩放下无关键遮挡或裁切。

## 不在本阶段内

- 机器人策略、模型训练、网络牌谱下载、视觉识别和手机图传。
- 从只有可见信息的中途快照唯一恢复真实暗手和牌山。原记录功能保留，但不能伪造隐藏状态补齐成真实对局。

## 兼容与推进方式

1. 阅读现有数据类、Recorder、窗口及测试，决定可复用部分；保留旧接口与记录格式。
2. 先完成无界面的真实牌山与普通摸打，通过库存守恒和可复现测试。
3. 完成观察接口，通过信息隔离与状态不可被外部修改的测试。
4. 接入图形牌桌，验证点击操作、四家视角和全知模式；保留错误与测试输出。
5. 运行旧测试与新增测试，实际检查界面，再更新已完成进度和运行说明。

游戏环境模块、观察对象的具体类名、牌面绘制方式与 UI 框架仍为实现选择；以上布局属于建议，用户已确认的是功能目标和图形化要求。
